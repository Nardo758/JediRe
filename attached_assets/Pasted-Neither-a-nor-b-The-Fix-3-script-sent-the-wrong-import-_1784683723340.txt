Neither (a) nor (b). The Fix 3 script sent the wrong import target.
The proforma-seeder and proforma-assumptions-bridge were importing LayeredValue from document-extraction/types.ts. The W1-6b script renamed that type to ExtractedFieldSources — but the fields are identical (resolved, resolution, platform, override, t12, etc.). The script only changed the name, not the body.
So the fix is not "create another type" (a) or "migrate 200 call sites" (b). It's: import ExtractedFieldSources from document-extraction/types.ts instead of canonical LayeredValue.
The Fix 3 script repointed them to canonical types/layered-value.ts, but canonical LayeredValue<T> has a completely different shape (value, source, confidence, layers). That's why ~220 errors appeared — structural mismatch, not missing imports.
